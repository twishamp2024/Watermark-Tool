# Deployment — ClipMark

ClipMark is distributed as a **sideloaded APK** via GitHub Releases. There is no backend, no store listing, and no telemetry.
Continuous Integration and Release Publishing are automated via GitHub Actions workflows in `.github/workflows/`.

## 1. Build

### Local Build
```bash
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release.apk
```

Release build type (`app/build.gradle.kts`):

| Setting | Value |
|---|---|
| `isMinifyEnabled` / `isShrinkResources` | `true` / `true` (R8; rules in `app/proguard-rules.pro` keep `ListenableWorker` constructors) |
| Signing | **Debug keystore** (`signingConfigs.getByName("debug")`) |
| Baseline profiles | Generated by AGP into `outputs/apk/release/baselineProfiles/` (no custom profile in the source) |
| R8 mapping | `app/build/outputs/mapping/release/`. Keep it for each distributed build to de-obfuscate stack traces. |

### CI / Release Automation (GitHub Actions)
- **CI Workflow** (`.github/workflows/ci.yml`): Runs on every push and pull request to `main`. Validates compilation, runs all unit tests (`./gradlew testDebugUnitTest`), and tests release assembly (`./gradlew assembleRelease`).
- **Release Workflow** (`.github/workflows/release.yml`): Triggered when a semantic version tag (e.g. `v1.0.0`) is pushed. Builds the release APK, computes SHA-256 checksums, and publishes a new GitHub Release with the attached APK and release notes.

## 2. Signing and secrets

* No secrets, API keys or external environment variables are required by the build or the app.
* Release is signed with the local debug key so that it installs directly on the user's phone without requiring complex key management.
* Before distributing on formal app stores (e.g. Google Play), a dedicated release `signingConfig` should be configured using repository secrets (`KEYSTORE_BASE64`, passwords).

## 3. Install

```bash
adb install -r app/build/outputs/apk/release/app-release.apk
```

Alternatively, download `clipmark-v*.apk` from GitHub Releases directly to the Android device and open it (the device must allow installs from unknown sources).

## 4. Versioning

* Versioning follows Semantic Versioning (`vMAJOR.MINOR.PATCH`).
* `versionCode` and `versionName` in `app/build.gradle.kts` are updated for each release. Android requires `versionCode` to increment for upgrades.
* The Settings screen displays `Version <versionName>` (via `BuildConfig`).

## 5. Rollback

Install the previous APK. If its `versionCode` is lower, uninstall first (`adb uninstall com.animecliplabs.clipmark`) or
use `adb install -r -d`. Uninstalling deletes presets, settings and history (unless they are restored from Android backup).
Exported photos in `Pictures/AnimeClips Watermarked/` are **not** deleted by an uninstall.

Data compatibility: stored JSON tolerates older and newer schemas (see [DATA_STORAGE.md](../02-architecture/DATA_STORAGE.md#4-serialization-rules-compatibility-contract)),
so a rollback should not crash on data written by a newer version.

## 6. Permissions in the shipped APK

Declared in `app/src/main/AndroidManifest.xml`:

| Permission | Purpose |
|---|---|
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `FOREGROUND_SERVICE_MEDIA_PROCESSING` | Batch worker in the foreground |
| `POST_NOTIFICATIONS` | Progress/finish notifications (runtime-requested once on Android 13+) |

These are added by the **merged manifest** from AndroidX WorkManager:

| Permission | Why it's there |
|---|---|
| `WAKE_LOCK` | WorkManager keeps the CPU awake while work runs |
| `ACCESS_NETWORK_STATE` | WorkManager's network constraints (unused by ClipMark; no network access occurs) |
| `RECEIVE_BOOT_COMPLETED` | WorkManager reschedules pending work after a reboot |
| `<package>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | AndroidX core, for internal non-exported receivers |

There is **no `INTERNET` permission**, ensuring 100% on-device processing and user privacy.

## 7. Platform requirements

minSdk 29 (Android 10), targetSdk 37. Foreground service type `mediaProcessing` is used on API 35+ and `dataSync` below.
