# Deployment — ClipMark

ClipMark is distributed as a **sideloaded APK** for personal use. There is no backend, no store listing,
no CI/CD pipeline and no release automation in the repository.

## 1. Build

```bash
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release.apk
```

Release build type (`app/build.gradle.kts`):

| Setting | Value |
|---|---|
| `isMinifyEnabled` / `isShrinkResources` | `true` / `true` (R8; rules in `app/proguard-rules.pro` keep `ListenableWorker` constructors) |
| Signing | **Debug keystore** (`signingConfigs.getByName("debug")`) |
| Baseline profiles | Generated by AGP into `outputs/apk/release/baselineProfiles/` (no custom profile in the source) |
| R8 mapping | `app/build/outputs/mapping/release/`. Keep it for each distributed build to de-obfuscate stack traces. |

## 2. Signing and secrets

* No secrets, API keys or environment variables are used by the build or the app.
* Release is signed with the local debug key so that it installs directly on the author's phone. This is **not suitable for
  distribution**: the debug key is machine-specific, so a build from another machine can't update an installed copy.
  Play Store also rejects debug-signed APKs.
* Before distributing, add a release `signingConfig` that reads the keystore path and passwords from `local.properties` or
  environment variables. Never commit the keystore or passwords. **Not yet decided: UNKNOWN / REQUIRES PRODUCT DECISION.**

## 3. Install

```bash
adb install -r app/build/outputs/apk/release/app-release.apk
```

Alternatively, copy the APK to the phone and open it (the phone must allow installs from that source).
Switching between a debug and a release build is possible only while both are signed with the same key, which is the case today.

## 4. Versioning

`versionCode = 1` and `versionName = "1.0.0"` in `app/build.gradle.kts`, bumped by hand. There is no changelog or tag scheme in the repo.
**Convention: UNKNOWN / REQUIRES PRODUCT DECISION.** Semantic versioning with `versionCode` incremented on every distributed
build is the usual choice. Android refuses to install a lower `versionCode` over a higher one.

The Settings screen shows `Version <versionName>` (via `BuildConfig`).

## 5. Rollback

Install the previous APK. If its `versionCode` is lower, uninstall first (`adb uninstall com.animecliplabs.clipmark`) or
use `adb install -r -d`. Uninstalling deletes presets, settings and history (unless they are restored from Android backup).
Exported photos in `Pictures/AnimeClips Watermarked/` are **not** deleted by an uninstall.

Data compatibility: stored JSON tolerates older and newer schemas (see [DATA_STORAGE.md](../02-architecture/DATA_STORAGE.md#4-serialization-rules-compatibility-contract)),
so a rollback should not crash on data written by a newer version.

## 6. Permissions in the shipped APK

Declared in `app/src/main/AndroidManifest.xml`:

| Permission | Purpose |
|---|---|
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `FOREGROUND_SERVICE_MEDIA_PROCESSING` | Batch worker in the foreground |
| `POST_NOTIFICATIONS` | Progress/finish notifications (runtime-requested once on Android 13+) |

These are added by the **merged manifest** from AndroidX WorkManager (verified in
`app/build/intermediates/merged_manifest/release/.../AndroidManifest.xml`):

| Permission | Why it's there |
|---|---|
| `WAKE_LOCK` | WorkManager keeps the CPU awake while work runs |
| `ACCESS_NETWORK_STATE` | WorkManager's network constraints (unused by ClipMark; no network access occurs) |
| `RECEIVE_BOOT_COMPLETED` | WorkManager reschedules pending work after a reboot |
| `<package>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | AndroidX core, for internal non-exported receivers |

There is **no `INTERNET` permission**, so the app cannot make network requests.

## 7. Platform requirements

minSdk 29 (Android 10), targetSdk 37. Foreground service type `mediaProcessing` is used on API 35+ and `dataSync` below.
